智能体设计模式 (Agentic Design Patterns) 全解析

作者：Antonio Gulli | 篇幅：570页，21章 + 附录

一、书籍概述

这是一本系统阐述 AI 智能体 (Agent) 架构设计模式 的实践指南。全书以”模式”为组织单元，每个模式包含：概念概述 → 应用场景 → 框架代码示例（LangChain / Google ADK / CrewAI 等多框架对比）→ 速览总结 → 关键要点。其核心理念是：构建可靠的 AI 智能体系统，不是靠一个万能的 prompt，而是靠一组精心设计的、可组合的架构模式。

二、21 种设计模式全景图

根据模式的性质与层次，可将全书 21 种模式归为四大类：

A. 核心流程模式（任务分解与执行）

模式 核心思想 一句话概括
1. 提示词链 (Prompt Chaining) 将复杂任务拆分为顺序执行的子任务，前一步输出作为后一步输入 “分而治之”的流水线
2. 路由 (Routing) 根据输入意图动态分发到不同专业处理器 “智能调度员”
3. 并行化 (Parallelization) 将无依赖的子任务并发执行以提升效率 “多线程工作”
6. 规划 (Planning) 智能体自主制定行动方案再逐步执行 “先谋后动”
20. 优先级排序 (Prioritization) 对多目标任务按重要性和紧急度排序执行 “要事优先”

B. 智能增强模式（能力扩展）

模式 核心思想 一句话概括
4. 反思 (Reflection) 生成 → 自我评审 → 修正的迭代循环（Producer-Critic 结构） “自我纠错”
5. 工具使用 (Tool Use / Function Calling) LLM 调用外部 API、数据库、代码解释器扩展能力边界 “赋予手脚”
8. 记忆管理 (Memory) Session（短期）+ State（工作区）+ MemoryService（长期）三层记忆 “记住上下文”
9. 学习与适应 (Learning & Adaptation) 从反馈中持续改进，避免重复犯错 “越用越聪明”
14. RAG 知识检索 (Knowledge Retrieval) 外部知识库检索增强生成质量与事实准确性 “查资料再回答”
17. 推理技术 (Reasoning) CoT/ToT/ReAct 等高级推理策略系统化应用 “深度思考”

C. 协作与通信模式（多智能体编排）

模式 核心思想 一句话概括
7. 多智能体协作 (Multi-Agent Collaboration) 多专业智能体分工合作，协调器统一调度 “团队作战”
10. MCP 协议 (Model Context Protocol) 模型与外部工具的标准化接口协议 “USB-C 接口”
15. A2A 通信 (Agent-to-Agent) 智能体之间的标准通信协议 “智能体间对话”
21. 探索与发现 (Exploration & Discovery) 智能体主动探索新思路、新方案（如 Google Co-Scientist） “科学假设生成”

D. 可靠性与运维模式（生产保障）

模式 核心思想 一句话概括
11. 目标设定与监控 (Goal Setting & Monitoring) 明确目标 → 跟踪进展 → 评估偏差的闭环 “航行仪表盘”
12. 异常处理与恢复 (Exception Handling & Recovery) 优雅降级、重试机制、备选路径 “容错机制”
13. 人机协同 (Human-in-the-Loop) 关键决策点引入人工审核与干预 “人机共治”
16. 资源感知优化 (Resource-Aware Optimization) 根据任务难度动态切换模型、控制成本 “勤俭持家”
18. 安全护栏 (Guardrails / Safety) 输入输出过滤、内容安全审查、约束边界 “安全围栏”
19. 评估与监控 (Evaluation & Monitoring) 智能体轨迹追踪、性能度量、持续评测 “质量管控”

三、四个核心模式深度解读

1. 提示词链 (Prompt Chaining)

问题：单一复杂 prompt 容易导致指令忽略、上下文漂移、错误传播、幻觉加剧。

解法：将任务拆成顺序执行的链式流水线，每步聚焦单一职责，输出采用 JSON 等结构化格式保证数据完整性。

关键实践：每步赋予不同角色（如”市场分析师”→”数据分析师”→”专业撰稿人”），结构化输出（JSON/XML）。

2. 反思 (Reflection)

核心架构：Producer-Critic 双智能体模型

  • Producer（生产者）：负责初次生成
  • Critic（评审者）：以不同角色（如”高级软件工程师”）审查输出，提供结构化反馈
  • 循环：Producer 根据 Critic 反馈修正，直至输出”完美”或达到最大迭代次数

价值：打破”自我审查”的认知偏差，模拟人类的”打草稿→检查→修改”过程。

3. 工具使用 (Tool Use / Function Calling)

本质：让 LLM 从”纯大脑”变成”有手有脚”的智能体。

  • LLM 识别意图 → 选择合适工具 → 生成函数调用 → 解析结果 → 继续推理
  • 工具可以是：搜索引擎、数据库、代码执行器、API 调用、文件系统等
  • 框架实践：LangChain 的 @tool 装饰器、Google ADK 的 FunctionTool

4. 多智能体协作 (Multi-Agent Collaboration)

通信拓扑：层级式（Coordinator→Sub-agents）、网状（Peer-to-Peer）、流水线式

实践框架：CrewAI 的角色定义 + 任务分配、Google ADK 的 sub_agents 自动委托机制

四、三大协议：MCP vs A2A vs Function Calling

这是全书最具前瞻性的部分：

维度 Function Calling MCP A2A
粒度 单次工具调用 标准化工具接口 智能体间通信
类比 调用一个函数 USB-C 接口标准 HTTP/REST 协议
解决的问题 “我该调哪个函数？” “如何统一接入各种工具？” “智能体之间如何对话？”
方向 LLM → 工具 工具 → 标准化 → LLM Agent ↔ Agent

MCP 让任何工具都能以统一协议被 LLM 调用（类似”万能遥控器”）；A2A 让不同团队的智能体可以互操作（类似”跨组织协作协议”）。

五、三层记忆架构

反思模式与记忆管理结合，让智能体从”每次重新开始”进化为”越用越懂你”。

六、完整智能体的构建配方

书中结论部分指出，一个生产级 AI 智能体的典型模式组合：

核心执行链：规划 制定方案 → 工具使用 扩展能力 → 反思 自我修正 → 人机协同 关键审核 → 安全护栏 风险拦截 → 评估监控 持续改进。

支撑层：MCP 做工具标准化、A2A 做多智能体通信、RAG 做知识增强、记忆管理 贯穿全流程。

七、一句话总结

这本书的本质是一本 “AI 智能体工程化的《设计模式》”——正如 GoF 的《设计模式》统一了面向对象编程的最佳实践，这本书试图统一智能体架构的设计语言。
