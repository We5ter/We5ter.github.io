AI-Infra-Guard AI-Infra-Guard

腾讯朱雀实验室的全栈 AI 红队平台：五层能力覆盖 AI 基础设施 CVE、Agent 失控、MCP 供应链、Skill 后门与越狱评测 A full-stack AI red teaming platform from Tencent Zhuque Lab: five capabilities spanning AI infrastructure CVEs, agent loss of control, the MCP supply chain, skill backdoors and jailbreak evaluation

腾讯朱雀实验室出品的 Apache-2.0 项目，6.6k star / 615 fork / 1918 commits。不是单个扫描器，是五个能力并列的平台：AI Infra Scan 指纹识别 146 个 AI 组件、匹配 2000+ CVE（只扫运行中服务地址，支持 CIDR 网段批量）；Agent Scan 是多 Agent 自动化框架（支持 Dify / Coze，10 个检测技能映射 OWASP ASI）；MCP Scan 覆盖 14 类风险、输出 SARIF、无需运行实例；Skill Scan 对齐 SkillTrustBench T01–T09，Top 模型 F1 约 0.98；Jailbreak Evaluation 基于 DeepTeam，支持 4 种多轮越狱攻击与跨模型对比。另含 Model & API Relay Checker 做模型指纹、Claude 签名验证与 LLM API 投毒检测。自带 FORGE-Bench（16 领域 / 1800 轨迹）、RogueHandoff-20、SkillJack 三个自研基准，3 篇论文（含 2 篇 Black Hat Europe 2025），被 19 篇学术论文引用。两个明确短板：README 自述无身份认证、不应部署公网；部分子模块未完成（4 个检测技能有 SKILL.md 但未注册 _DETECTION_SKILLS，实际从不运行）。 An Apache-2.0 project from Tencent Zhuque Lab with 6.6k stars / 615 forks / 1,918 commits. Not a single scanner but a platform of five peer capabilities: AI Infra Scan fingerprints 146 AI components and matches 2,000+ CVEs (live service addresses only, CIDR ranges supported); Agent Scan is a multi-agent automation framework (Dify / Coze supported, 10 detection skills mapped to OWASP ASI); MCP Scan covers 14 risk classes, emits SARIF, and needs no running instance; Skill Scan aligns to SkillTrustBench T01–T09 with a top-model F1 around 0.98; Jailbreak Evaluation builds on DeepTeam with four multi-turn attack methods and cross-model comparison. A Model & API Relay Checker adds model fingerprinting, Claude signature verification and LLM API poisoning detection. Ships three homegrown benchmarks — FORGE-Bench (16 domains / 1,800 trajectories), RogueHandoff-20 and SkillJack — plus three papers (two from Black Hat Europe 2025), and is cited by 19 academic papers. Two clear caveats: the README states there is no authentication and it should not be deployed on public networks, and several sub-modules are unfinished (four detection skills have a SKILL.md but were never registered in _DETECTION_SKILLS, so they never run).

NVIDIA OpenShell NVIDIA OpenShell

面向自主 AI Agent 的安全私有运行时：用声明式 YAML 策略在文件系统、网络、进程、凭证四个维度设界，凭证只在策略放行后注入授权端点 A safe, private runtime for autonomous AI agents: declarative YAML policies enforce boundaries across filesystem, network, process and provider access, and credentials only flow into policy-admitted endpoints

Rust 编写的 8.7k star 项目，Apache-2.0。定位是 autonomous AI agents 的运行时管控：把 agent 关进一个被策略包围的隔离容器，默认最小出站，按 "允许 / 凭 / 拒" 三态拦截每一次 outbound。四个保护层：Filesystem 与 Process 在沙箱创建时锁定，Network 与 Providers 可运行时热更新。Provider 模型把凭证绑在端点上，凭证从不落盘，运行时以环境变量注入被策略放行的端点，网络策略细到 HTTP method 与 path（L7）。支持 Docker / Podman / MicroVM / Kubernetes 四种算力后端，SDK 覆盖 Python / TypeScript / Go / Rust，可托管 Claude Code / Codex / OpenCode / Copilot CLI。NVIDIA 官方出品（docs.nvidia.com/openshell），目前 alpha（0.1.0 即将发布），403 个 open issues。 An 8.7k-star Rust project under Apache-2.0. Positioned as runtime control for autonomous AI agents: the agent runs in an isolated container wrapped in declarative policy, every outbound request goes through a three-state gate (allow / bind credentials / deny). Four protection layers: Filesystem and Process are locked at sandbox creation, Network and Providers are hot-reloadable at runtime. The Provider model binds credentials to authorized endpoints — keys never touch the sandbox filesystem, they are injected as environment variables at runtime only into requests the policy admits, with the network policy enforced at HTTP method and path granularity (L7). Four compute backends (Docker, Podman, MicroVM, Kubernetes), SDKs for Python, TypeScript, Go and Rust, and a curated set of supported agents (Claude Code, Codex, OpenCode, Copilot CLI). Officially from NVIDIA (docs.nvidia.com/openshell), currently in alpha with 0.1.0 imminent and 403 open issues.

第 004 期 No. 4 2026.9.21 周一 Sep 21, 2026

PentAGI PentAGI

全自主渗透平台：Docker 沙箱里跑 20+ 工具，13 个 agent 角色分工，四道闸门防止跑飞 A fully autonomous pentesting platform: 20+ tools in a Docker sandbox, 13 specialized agent roles, and four supervision gates to stop runaway runs

Go 写的 24.8k star 项目，MIT。五层平台结构：核心服务（React UI + Go REST/GraphQL API + PostgreSQL/pgvector）、可选知识图谱（Graphiti + Neo4j）、监控栈（Grafana / VictoriaMetrics / Jaeger / Loki）、分析（Langfuse + ClickHouse）、安全工具（沙箱内 20+ 工具 + 隔离浏览器）。13 个 agent 角色分通用与受限两档，四道监管：工具调用硬上限（100 / 20，常开）、Reflector（连续 3 次生成不出工具调用就介入，常开）、Execution Monitoring（Beta，Mentor 盯循环）、Task Planning（Beta，先拆 3-7 步再动手）。官方维护了一份 vLLM + Qwen3.5-27B-FP8 气隙部署指南，国产模型是一等公民。 A 24.8k-star Go project under MIT. Five platform layers: core services (React UI, Go REST/GraphQL API, PostgreSQL with pgvector), optional knowledge graph (Graphiti plus Neo4j), monitoring (Grafana, VictoriaMetrics, Jaeger, Loki), analytics (Langfuse plus ClickHouse), and sandboxed security tooling (20+ tools and an isolated scraper browser). Thirteen agent roles split into general and limited tiers, supervised by four gates: hard tool-call caps (100 / 20, always on), a Reflector that steps in after three failed tool calls (always on), Execution Monitoring (Beta, a Mentor agent watching for loops), and Task Planning (Beta, decomposing the goal into 3-7 steps first). The authors maintain an official vLLM plus Qwen3.5-27B-FP8 guide for fully air-gapped deployment.

Cairn Cairn

通用状态空间搜索引擎：不定义角色与工作流，给起点和终点，让 Agent 在黑板上自己搜路 A general state-space search engine: no roles, no workflows — hand it an origin and a goal and let agents find the path on a shared blackboard

Python 写的 2.8k star 项目。黑板架构 + 事实/意图图，只有 Fact / Intent / Hint 三个原语；Worker 跑 OODA 循环，靠 Stigmergy 间接协作，彼此不通信。Bootstrap / Reason / Explore 三类任务由同一个 Worker 执行，角色在运行时长出来而非写死。腾讯云黑客松 AI 渗透挑战赛第二届，610 支队伍里唯一 AK（54/54）。AGPL-3.0。 A 2.8k-star Python project built on a blackboard architecture with an explicit fact-intent graph: just three primitives — Fact, Intent, Hint. Workers run an OODA loop and coordinate purely through stigmergy, with no direct agent-to-agent messaging. Bootstrap / Reason / Explore are all executed by the same worker, so roles emerge at runtime instead of being hardcoded. At the Tencent Cloud Hackathon AI Pentesting Challenge (2nd edition) it was the only team out of 610 to AK, solving 54/54. AGPL-3.0.
